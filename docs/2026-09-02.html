Reasoning 모델을 더 효율적으로 가르치는 방법

대형 모델 지식 전달로 추론 비용 절감

Knowledge DistillationOn-Policy DistillationDense FeedbackSparse FeedbackExposure Bias
원본 보기 →
핵심 포인트
· 교사 모델의 토큰 확률 분포를 학생 모델에 맞추는 Knowledge Distillation은 Dense Feedback을 제공한다.
· On-Policy Distillation은 학생이 생성한 답을 교사가 평가해 토큰‑레벨 피드백을 주어 Exposure Bias를 완화한다.
· Sparse Feedback(최종 보상)과 Dense Feedback(토큰별 확률) 사이의 차이를 이해하고, OPD와 최신 연구(Agarwal et al., 2023)를 활용해 학습 파이프라인을 설계한다.
적용 아이디어
💡 학생 모델이 자체 생성한 응답을 교사 모델에 전달해 토큰‑레벨 확률을 loss에 활용하는 On‑Policy Distillation 파이프라인을 구축한다.
💡 정적 데이터셋 대신 학생 모델의 Rollout을 이용해 동적 학습 데이터를 생성함으로써 Exposure Bias를 감소시키고, Dense Feedback을 활용한 미세 조정을 수행한다.
퀴즈
Q1. 다음 중 Dense Feedback의 특징이 아닌 것은?
A) 교사 모델이 각 토큰의 확률 분포를 제공한다
B) 학생 모델에 최종 정답 여부만 보상한다
C) 피드백이 토큰 수준에서 세밀하게 제공된다
D) 학습 신호가 토큰별 선호도를 반영한다
정답 보기
✓ B) 학생 모델에 최종 정답 여부만 보상한다
Sparse Feedback는 최종 정답 여부만 보상하는 반면, Dense Feedback은 각 토큰의 확률 분포와 선호도를 제공한다.

Python의 멀티프로세싱과 Airflow, 그리고 관련된 문제 해결기 1편

Airflow 멀티프로세싱으로 병렬·격리 확보

AirflowPythonforkspawnGIL
원본 보기 →
핵심 포인트
· Airflow는 task의 병렬 실행과 격리 두 가지 요구를 만족해야 한다.
· Python GIL 때문에 Airflow는 멀티프로세싱을 선택해 CPU 병렬성을 확보한다.
· fork는 COW로 메모리를 공유하고, spawn은 새 인터프리터를 시작해 모듈 오염을 방지한다.
적용 아이디어
💡 Unix 환경에서 Airflow task 실행 시 fork start method를 사용해 메모리 사용량을 최소화하고 CPU 코어를 효율적으로 활용한다.
💡 모듈 오염이나 코드 변경 반영이 중요한 경우 Airflow task를 spawn start method로 실행하도록 설정해 격리성을 강화한다.
퀴즈
Q1. Python 멀티프로세싱에서 메모리를 부모와 공유하는 방식은?
A) spawn
B) fork
C) forkserver
D) thread
정답 보기
✓ B) fork
fork는 Unix의 fork 시스템 콜을 사용해 페이지 테이블만 복사하고 물리 메모리를 공유하는 Copy-on-Write 방식을 적용한다.
Q2. Airflow task가 반드시 만족해야 하는 두 핵심 요구 사항은?
A) Scalability와 Security
B) Parallelism와 Isolation
C) Latency와 Throughput
D) Fault Tolerance와 Monitoring
정답 보기
✓ B) Parallelism와 Isolation
본문에서 Airflow는 병렬성(parallelism)과 격리성(isolation)을 핵심 요구 사항으로 제시한다.
