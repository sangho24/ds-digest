웹뷰 다음의 레일을 깔다: 당근이 Lynx를 선택한 이유

첫 화면 로딩을 최소화하는 Lynx 도입 사례

LynxPrimJSQuickJSRspeedyIFR
원본 보기 →
핵심 포인트
· Lynx는 PrimJS(QuickJS 기반) 경량 JS 엔진을 사용해 런타임 초기화 비용을 크게 낮춰 첫 화면 렌더링을 가속화한다.
· 메인 스레드와 백그라운드 스레드로 구성된 Dual‑Thread Architecture가 UI 그리기와 React 라이프사이클을 분리해 Instant First‑Frame Rendering을 제공한다.
· Rspeedy(Rspack·Rsbuild 기반) 번들러로 번들을 CDN에 분리 배포해 프론트엔드 코드를 앱 바이너리와 독립적으로 업데이트할 수 있다.
적용 아이디어
💡 PrimJS와 같은 경량 임베디드 JavaScript 엔진을 모바일 UI 모듈에 도입해 초기화 지연을 수 ms 수준으로 감소시킨다.
💡 Lynx의 Dual‑Thread IFR 패턴을 참고해 메인 스레드에서 번들과 핵심 데이터를 사전 로드하고, 백그라운드에서 React 로직을 처리해 첫 화면을 즉시 표시한다.
퀴즈
Q1. Lynx가 메인 스레드 런타임에 사용하는 JavaScript 엔진은 무엇인가?
A) V8
B) QuickJS
C) SpiderMonkey
D) JavaScriptCore
정답 보기
✓ B) QuickJS
Lynx는 PrimJS라는 경량 엔진을 사용하며, PrimJS는 QuickJS 기반이다.
Q2. Lynx가 Instant First‑Frame Rendering을 달성하기 위해 채택한 아키텍처는?
A) Single‑threaded
B) Dual‑thread (main + background)
C) Server‑side rendering
D) WebAssembly
정답 보기
✓ B) Dual‑thread (main + background)
Lynx는 메인 스레드와 백그라운드 스레드가 각각 UI 렌더링과 React 라이프사이클을 담당하는 Dual‑Thread Architecture를 사용한다.

Laying the Rails Beyond WebView: Why Karrot Chose Lynx

WebView 로딩 지연을 줄이는 Lynx 도입 평가 과정

LynxQuickJSWebViewService WorkerReact
원본 보기 →
핵심 포인트
· WebView 초기 로딩 비용이 사용자 경험 병목이며, 첫 프레임부터 실제 UI를 렌더링할 수 있는 런타임이 필요하다
· Lynx는 작은 JavaScript 엔진(PrimJS/QuickJS)과 빠른 시작을 제공해 네이티브 앱에 임베드하기 적합하다
· 도입 조건으로 화면별 점진적 적용, 독립 배포, 최소 인력으로 구현 가능, 기존 WebView 복구 경로 확보가 필요했다
적용 아이디어
💡 WebView 대신 Lynx를 도입해 핵심 화면의 첫 프레임부터 실제 UI를 표시하여 로딩 인지 감소
💡 QuickJS(PrimJS)를 경량 JavaScript 엔진으로 임베드해 모바일 UI 런타임의 시작 시간을 최소화
퀴즈

A) 앱 바이너리 크기 감소
B) 첫 프레임부터 로딩 지연 없이 UI 표시

D) 서버 사이드 렌더링 활성화
정답 보기
✓ B) 첫 프레임부터 로딩 지연 없이 UI 표시
본문에서는 사용자가 로딩을 전혀 인지하지 못하도록 첫 화면부터 실제 UI를 렌더링하는 것이 목표라고 명시했다.
