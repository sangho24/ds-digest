Recursive Video In-Context Learning for Agentic Robot

영상 계층화로 로봇 학습 효율·성공률 크게 향상

배경과 위치
LLM 기반 로봇 에이전트는 텍스트 메모리만으로는 세밀한 시각 정보를 전달하기 어려워 기존에는 전체 시연 영상을 프롬프트에 넣어 비효율적이었다. RV-ICL는 시연 영상을 계층화해 필요 시 세부 클립을 읽어들이는 훈련‑무료 접근으로, 멀티모달 인‑컨텍스트 학습과 재귀적 작업 분해 흐름에 속한다. 기존 방법 대비 메모리·연산 효율과 성공률을 동시에 끌어올렸다.
실행가능성 7
깊이 6
  • · RV-ICL는 단일 시연 영상을 계층 구조로 변환해 에이전트가 탐색하도록 하여 전체 영상을 로드하지 않는다.
  • · 계층은 전체 키프레임→단계→순간→짧은 클립 순으로 세분화되며, 실행 중 필요 시 현재 하위 목표의 클립만 로드한다.
  • · 이 방법으로 LIBERO-PRO 성공률이 92.6%→96.5%, LIBERO-Plus가 86.7%→95.8%로 향상된다.
Action Items
  • 자율주행 시뮬레이션에서 전체 경로는 키프레임으로, 복잡한 차선 변경은 짧은 클립으로 제공해 실시간 의사결정 지연을 감소한다.
  • 산업용 조립 로봇에 시연 영상을 단계·클립 계층으로 구성해 현재 조립 단계에 맞는 짧은 클립만 로드함으로써 메모리 사용량을 줄이고 오류율을 낮춘다.
  • 의료 AI 어시스턴트가 수술 시연 영상을 단계·클립으로 구조화해, 질문 시 해당 단계의 짧은 클립을 제공해 실시간 가이드 정확성을 높인다.

① 키프레임 → 단계 → 순간 → 짧은 클립

③ 필요 시 계층에 재진입해 현재 하위 목표의 클립만 로드한다
④ 더 큰 LLM을 적용한다
③ 필요 시 계층에 재진입해 현재 하위 목표의 클립만 로드한다
핵심은 에이전트가 계획 단계에서 거친 레벨을 읽고, 실행 중 세부가 필요하면 계층에 재진입해 해당 클립만 로드함으로써 효율과 정확성을 동시에 개선한다.

Aurora MySQL 인덱스 DDL이 Reader 버퍼풀을 비운다?

Aurora 버퍼가 인덱스 INVISIBLE 때 비워짐

실행가능성 7
깊이 8
  • · Aurora Reader는 인덱스 INVISIBLE DDL 시에 버퍼풀 캐시가 전부 무효화돼 CPU와 ReadIOPS 급증을 일으킨다.
  • · DDL 종류에 따라 Reader 캐시 영향이 다르며, INPLACE rebuild(예: 컬럼 타입 변경) 시에는 캐시가 소멸하지만 INSTANT/INPLACE without rebuild는 유지돼야 한다.
  • · 인덱스 사용 여부 판단은 performance_schema.table_io_waits_summary_by_index_usage 를 활용하고, 인덱스를 INVISIBLE 로 전환해 테스트 후 DROP 하는 절차가 안전하다.
Action Items
  • performance_schema 기반 사용량 분석을 PostgreSQL의 pg_stat_user_indexes와 결합해 오래된 물리적 뷰를 안전하게 비활성화하고 단계적으로 삭제한다.
  • 인덱스를 INVISIBLE 로 전환하는 방식을 다른 DBMS(예: Oracle)에서 스키마 변경 전 기능 플래그로 활용해 서비스 중단 없이 구조 변경을 검증한다.
  • Reader‑Writer 구조를 가진 분산 DB에서 DDL 후 BufferPool 히트율을 모니터링해 캐시 무효화 패턴을 조기에 감지하고 자동 롤백 정책을 적용한다.
퀴즈 2문항
Aurora Reader에서 인덱스 INVISIBLE 로 전환했을 때 CPU·ReadIOPS가 급증하는 주된 원인은?
① Reader 버퍼풀의 해당 테이블 캐시 페이지가 전부 소멸한다
② Writer가 페이지를 재작성한다
③ Invisible 인덱스가 전체 테이블 스캔을 유발한다
④ CloudWatch 지표가 오작동한다
① Reader 버퍼풀의 해당 테이블 캐시 페이지가 전부 소멸한다
Reader는 자체 버퍼풀을 가지고 있으며, INVISIBLE DDL 시 내부적으로 캐시된 페이지를 무효화해 스토리지에서 다시 읽게 되므로 CPU와 I/O가 급증한다.
사용되지 않는 인덱스를 찾기 위해 본문에서 사용한 쿼리는?
① SELECT * FROM information_schema.tables;
② SELECT object_name, index_name, count_star FROM performance_schema.table_io_waits_summary_by_index_usage;
③ SHOW INDEX FROM 테이블;
④ EXPLAIN SELECT ...
② SELECT object_name, index_name, count_star FROM performance_schema.table_io_waits_summary_by_index_usage;
performance_schema.table_io_waits_summary_by_index_usage 테이블은 인덱스별 읽기·쓰기 횟수를 제공해 사용량이 0인 인덱스를 식별할 수 있다.
