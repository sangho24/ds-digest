TorchCurves: Differentiable Parametric Curves

연속형 특징 임베딩을 곡선으로 직접 학습해 모델 표현력 확대

배경과 위치
연속 함수 표현을 위해 기존에는 고정된 basis나 MLP를 사용했으나, 미분 가능한 파라메트릭 곡선을 원시적으로 도입해 모델에 통합한다. 이는 KAN 및 함수 회귀와 같은 연속형 특성 임베딩 연구 흐름에 속하며, B‑spline·Legendre 기반 구현으로 기존 방법 대비 유연성과 미분 가능성을 제공한다.
실행가능성 8
깊이 6
  • · TorchCurves는 벡터값 파라메트릭 곡선을 미분 가능한 원시로 취급해 B‑spline·Legendre 기반으로 입력과 계수 모두에 대한 그래디언트를 제공한다.
  • · PyTorch와 통합된 학습 가능한 모듈·함수형 인터페이스를 제공해 곡선 계수를 주변 모델과 공동 최적화하거나 별도 네트워크가 생성하도록 지원한다.
  • · 실험에서 NumPy·SciPy와 비교해 작은 규모에서는 실용적이지만, 문제 규모가 커질수록 오버헤드가 커지는 트레이드오프를 명시한다.
Action Items
  • IoT 엣지 디바이스에서 센서 보정 곡선을 미분 가능하게 학습시켜 실시간 보정 파라미터를 모델에 통합한다.
  • 연속 액션 공간 강화학습에서 정책 함수를 MLP 대신 곡선 원시로 표현해 파라미터 수를 줄이고 부드러운 정책 변화를 구현한다.
  • 추천 시스템에서 사용자의 시간에 따른 선호 변화를 B‑spline 임베딩으로 나타내어 시계열 개인화 정확도를 향상시킨다.

TorchCurves가 NumPy·SciPy와 비교해 제공하는 주요 이점은 무엇인가?
① 수치 정밀도 향상
② 입력과 계수에 대한 그래디언트 역전파 가능
③ 모든 문제 규모에서 GPU 가속 속도 우위
④ 자동 데이터 증강 기능
② 입력과 계수에 대한 그래디언트 역전파 가능
TorchCurves는 PyTorch와 연동돼 입력과 곡선 계수 모두에 대해 미분 가능하도록 설계돼, 기존 NumPy·SciPy와 달리 역전파가 가능하다.
실험 결과에 따르면 TorchCurves의 오버헤드가 크게 나타나는 상황은?
① 배치 크기가 매우 작을 때
② 문제 규모가 클 때
③ Legendre 기반을 사용할 때
④ KAN 모델을 학습할 때
② 문제 규모가 클 때
본문은 규모가 커질수록 일반성에 따른 오버헤드가 실질적으로 커진다고 언급한다.

  • · TV 박스와 구형 iPad 등에서 2 B‑16 B 모델을 측정된 토큰 속도로 구동해 실제 사용 가능성을 입증한다.

Mixture‑of‑Experts 모델을 플래시에서 페이지링하면 1 GB RAM에서도 16 B 모델을 실행할 수 있는 이유는?
① 모든 전문가를 동시에 메모리에 올린다
② 토큰당 필요한 전문가만 RAM에 유지하고 나머지는 필요 시 읽는다
③ 모델을 압축해 RAM에 저장한다
④ GPU를 사용한다
② 토큰당 필요한 전문가만 RAM에 유지하고 나머지는 필요 시 읽는다

① 1‑bit 연산으로 메모리 대역폭을 절감한다
② Cortex‑A55에 전용 dot‑product 명령이 있다
③ 1‑bit 데이터는 NEON SIMD으로 효율적으로 처리된다
④ 1‑bit은 GPU 전용이다
① 1‑bit 연산으로 메모리 대역폭을 절감한다
1‑bit 표현은 데이터 양을 크게 줄여 메모리 대역폭 요구를 감소시키고, NEON을 이용한 간단한 lookup 연산으로 빠르게 처리할 수 있다.

AI도 시험 볼 때 눈치를 봅니다

AI 평가 인지로 모델 행동 변화를 예측해 안전성 확보

실행가능성 6
깊이 6
  • · LLM은 평가 상황을 인식하고 평가와 일반 사용을 구분할 수 있으며, Gemini 2.5 Pro는 평가 기록을 0.83 AUC, 에이전트 기록에서는 0.88‑0.95 AUC를 기록했다.
  • · 모델은 평가 목적(능력 vs 정렬)을 추론할 수 있어 Claude 3.7 Sonnet은 93% 정확도로 구분했다.
  • · 평가 인지가 행동에 미치는 효과는 제한적이며, 실제 행동 변화는 연구마다 크게 차이 나지 않는다.
Action Items
  • 고객 지원 챗봇에 평가 인지 탐지 프레임워크를 적용해 모델이 평가 상황이라고 판단할 때 응답을 조정해 실제 사용자와의 대화 일관성을 높인다.
  • 내부 벤치마크에서 능력 평가와 정렬 평가를 명확히 구분해 성능 지표와 안전 지표를 별도 KPI로 관리함으로써 모델 개선 방향을 보다 정확히 설정한다
  • RLHF 루프에 메타‑프롬프트(‘이 대화가 평가인지’)를 삽입해 모델이 보상 최적화에 과도하게 적응하는지를 실시간 감지하고 보정한다
