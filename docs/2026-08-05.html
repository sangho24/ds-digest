Oracle cut its Always Free ARM limits to 2 OCPU / 12GB, enforced Aug 18

무료 ARM 인스턴스 용량 감소, 비용·환경 재조정 필요

OracleAlways FreeAmpere A1OCPUARM
원본 보기 →
핵심 포인트
· Oracle은 2026년 8월 18일부터 무료 ARM 인스턴스 한도를 2 OCPU·12 GB RAM으로 축소한다.
· 한도는 테넌시 전체에 적용되며 초과 시 자동으로 인스턴스가 종료된다.
· 사용자는 OCI 콘솔에서 인스턴스를 리사이즈하거나 통합·삭제해 기한 전에 조치해야 한다.
적용 아이디어
💡 OCI API를 활용해 현재 무료 ARM 사용량을 정기적으로 모니터링하고, 한도 초과 위험이 감지되면 자동으로 인스턴스를 2 OCPU·12 GB 이하로 리사이즈하거나 불필요한 인스턴스를 종료하도록 스크립트를 구현한다.
💡 무료 ARM 인스턴스를 x86 마이크로 인스턴스로 전환하거나, 필요 시 유료 ARM 인스턴스로 마이그레이션해 비용과 가용성을 최적화한다.
퀴즈
Q1. Oracle이 2026년 8월 18일부터 적용하는 새로운 무료 ARM 한도는?
A) 4 OCPU·24 GB
B) 2 OCPU·12 GB
C) 1 OCPU·6 GB
D) 제한 없음
정답 보기
✓ B) 2 OCPU·12 GB
본문에 새 한도가 ‘Up to 2 OCPUs, Up to 12 GB of memory’라고 명시되어 있다.
Q2. 새 한도 변경에 영향을 받지 않는 인스턴스 유형은?
A) ARM 인스턴스
B) x86 마이크로 인스턴스
C) 모든 무료 인스턴스
D) 유료 인스턴스
정답 보기
✓ B) x86 마이크로 인스턴스
본문에 x86 마이크로 인스턴스는 기존 2 × 1 OCPU/1 GB 한도로 그대로 유지된다고 언급된다.

Rust-lang/rust is adopting an LLM policy

rust-lang/rustLLMLarge Language ModelGitHubRust
원본 보기 →
핵심 포인트
· Rust 프로젝트가 monorepo에 대한 LLM 사용 정책을 도입했다
· 정책은 리뷰어, PR 작성자, 이슈 발견자, LLM 인용 댓글 작성자에게 적용된다
· 목표는 투명성 유지, 리뷰 부담 감소, 노력 신호 보존이다
적용 아이디어
💡 Rust와 유사한 내부 LLM 사용 가이드라인을 수립해 코드 기여 시 책임과 검토 절차를 명시한다
💡 LLM 생성 코드를 제출할 때 출처를 명시하고 리뷰 체크리스트에 LLM 사용 여부를 확인하는 단계 추가
퀴즈
Q1. 새로운 Rust LLM 정책이 적용되는 그룹은?
A) 오직 PR 작성자만
B) 리뷰어·PR 작성자·이슈 발견자·LLM 인용 댓글 작성자
C) 프로젝트 유지관리자만
D) 모든 기여자
정답 보기
✓ B) 리뷰어·PR 작성자·이슈 발견자·LLM 인용 댓글 작성자

✓ B) 정제된 결과가 노력 신호를 숨김·리뷰 부담 증가·LLM 복사·붙여넣기 시간 낭비
