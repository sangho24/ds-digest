Knowledge-as-Skill: A Structural Design for Autonomous Knowledge-Base Use by LLM Agents

LLM 에이전트가 지식베이스를 스스로 탐색

배경과 위치
전통적인 RAG는 검색·결합·생성 순서에서 모델이 아닌 파이프라인이 검색을 결정한다는 한계가 있다. 본 논문은 메타데이터와 계층적 문서 구조를 활용해 에이전트가 스스로 지식베이스를 탐색하도록 하는 Knowledge-as-Skill 방식을 제안하며, 이는 LLM 기반 에이전트의 자율 검색 및 활용 연구 흐름에 속한다.
실행가능성 7
깊이 6
  • · 전통적인 RAG 파이프라인은 모델 대신 검색 결정을 수행해 에이전트의 자율성을 제한한다.
  • · Knowledge-as-Skill은 SKILL.md, index.md, YAML 메타데이터 문서의 3계층 구조로 지식베이스를 발견·탐색·자기 기술화한다.
  • · WixQA 벤치마크에서 사실성·컨텍스트 리콜이 기존 Corpus2Skill 대비 크게 향상되었다.
Action Items
  • 기업 내부 정책 문서를 Knowledge-as-Skill 구조로 정리해 AI 챗봇이 정책을 자동으로 찾아 답변하도록 한다.
  • 고객 지원 티켓 데이터베이스에 3계층 메타데이터를 적용해 LLM 에이전트가 필요한 티켓을 선택·조회하고 불필요한 조회를 줄인다.
  • 코드 스니펫 라이브러리에 YAML 앞머리 메타데이터를 넣어 LLM 코드 어시스턴트가 유형·출처에 따라 적절한 스니펫을 탐색하도록 한다.
퀴즈 2문항
왜 기존 RAG 파이프라인이 에이전트의 검색 결정을 제한하는가?
① 모델이 외부 지식에 접근하지 못한다
② 검색·결합·생성 단계가 고정돼 모델이 언제 검색할지 선택 못한다
③ 모델이 메타데이터를 이해하지 못한다
④ 에이전트가 프롬프트를 생성하지 못한다
② 검색·결합·생성 단계가 고정돼 모델이 언제 검색할지 선택 못한다
RAG는 retrieve‑concatenate‑generate 순서가 고정돼 모델이 스스로 검색 시점이나 중단을 결정할 수 없기 때문에 에이전트의 자율성이 제한된다.
Knowledge-as-Skill 구조의 탐색 레이어는 어떤 역할을 하는가?
① 문서 내용 요약 제공
② 디렉터리별 index.md 제공
③ YAML 메타데이터 정의
④ SKILL.md 작성
② 디렉터리별 index.md 제공
탐색 레이어는 각 디렉터리에 index.md 파일을 두어 해당 디렉터리의 문서들을 탐색할 수 있게 한다.

왜 RLHF로 학습된 언어 모델이 출력하는 '확신도' 값은 신뢰하기 어려운가?
① 모델은 확신도를 직접 계산하지 않고 다음 토큰 예측 확률을 텍스트 형태로 변환한다
② RLHF는 확신도를 고정값으로 학습한다
③ 모델은 항상 0.5로 출력한다
④ 확신도는 사후 학습 과정에서 무작위로 조정된다
① 모델은 확신도를 직접 계산하지 않고 다음 토큰 예측 확률을 텍스트 형태로 변환한다
RLHF 모델은 다음 토큰의 확률을 기반으로 텍스트를 생성하므로, 표시되는 '확신도'는 실제 확률이 아니라 토큰 선택 과정의 산출물이며 캘리브레이션이 맞지 않는다.
System One Model과 기존 Structured Output 방식의 주요 차이점은?
① System One Model은 문장을 생성하고 Structured Output은 선택만 제공한다
② System One Model은 처음부터 결정(값·확률) 형태로 출력하고 병렬 계산한다
③ Structured Output은 빠르고 비용이 적으며 System One Model은 느리다
④ 두 방식은 동일하다
② System One Model은 처음부터 결정(값·확률) 형태로 출력하고 병렬 계산한다
System One Model은 질문에 대해 선택·확률 등 결정값을 직접 반환하고 한 번의 쿼리에서 병렬로 계산해 속도와 비용을 절감한다, 반면 Structured Output은 생성형 모델이 텍스트를 만든 뒤 구조화하는 과정이다.
