핵심 포인트
· Slow query aggregating millions of series caused vmselect OOM; mitigated by query splitting and resource‑limit flags
· Analyzed vmstorage IndexDB rotation to redesign retention period policy
· Filtered out non‑service containers at collection stage to curb metric influx
적용 아이디어
💡 Apply vmselect resource‑limit flags (e.g., -search.maxUniqueTimeseries, -search.maxMemoryPerQuery) to prevent OOM in high‑cardinality workloads

퀴즈
Q1. Which vmselect flag limits the maximum memory a single query can use?
A) -search.maxUniqueTimeseries
B) -search.maxQueryDuration
C) -search.maxMemoryPerQuery
D) -memory.allowedPercent
정답 보기
✓ C) -search.maxMemoryPerQuery
-search.maxMemoryPerQuery sets the upper bound of memory that a single query may consume, helping avoid OOM.
Q2. In vmstorage, what is the primary purpose of IndexDB?
A) Store compressed time‑series data
B) Manage indexes for series lookup
C) Handle query aggregation
D) Rotate retention periods
정답 보기
✓ B) Manage indexes for series lookup
IndexDB holds the index structures that allow vmstorage to quickly determine whether a time series exists and retrieve its TSID.

핵심 포인트
· 일급 컬렉션은 컬렉션만을 상태로 가지고, 다른 멤버 변수를 포함하지 않아야 함.
· 일급 컬렉션 도입으로 비즈니스 로직 중복을 제거하고 코드 가독성을 높인다.
· 캡슐화와 응집도를 높여 유지보수와 변경에 강한 구조를 만든다.
적용 아이디어
💡 프로젝트의 도메인 컬렉션을 일급 컬렉션 클래스로 리팩터링하여 비즈니스 로직을 해당 클래스에 집중시킨다.
💡 서비스 레이어에서 리스트 파라미터 대신 일급 컬렉션 타입을 도입해 파라미터 순서 실수를 방지한다.
퀴즈
Q1. 일급 컬렉션의 정의는?
A) 컬렉션과 다른 멤버 변수를 함께 가진 클래스
B) 컬렉션만을 상태로 가지고 다른 멤버 변수가 없는 클래스
C) 원시 타입을 캡슐화한 클래스
D) 데이터베이스 테이블
정답 보기
✓ B) 컬렉션만을 상태로 가지고 다른 멤버 변수가 없는 클래스
텍스트에서는 일급 컬렉션을 컬렉션 외 다른 멤버 변수가 없는 클래스로 정의하고 있다.
Q2. 일급 컬렉션을 도입했을 때 기대되는 장점이 아닌 것은?
A) 중복 비즈니스 로직 제거
B) 파라미터 순서 실수 감소
C) 실행 속도 향상
D) 도메인 규칙 보장
정답 보기
✓ C) 실행 속도 향상
텍스트에서는 실행 속도 향상에 대한 언급이 없으며, 다른 선택지는 모두 언급된 장점이다.
