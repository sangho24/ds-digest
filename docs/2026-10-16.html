  • 메시지 큐 소비자에게 DiffTry식 무상태 백오프 전략을 적용해 소비자 폭풍을 방지하고 시스템 안정성을 높인다

실행가능성 7
깊이 6
  • · Dual package(ESM+CJS) 로드 시 동일 패키지가 두 번 로드돼 상태가 분리되는 Dual package hazard가 발생한다.
  • · import와 require가 서로 다른 구현을 읽어 컨텍스트와 캐시가 별도 객체로 생성된다.
  • · 토스뱅크는 이러한 문제를 해결하기 위해 패키지를 ESM 전용으로 제공하도록 전환했다.
Action Items

  • package.json의 exports 필드를 활용해 GPU와 CPU 구현을 구분해 제공함으로써 환경별 최적화된 코드를 안전하게 선택한다.
  • CI 파이프라인에 Dual package hazard 검사를 추가해 import와 require가 동시에 사용되는 경우를 사전에 차단한다.
퀴즈 2문항
import와 require가 같은 패키지를 로드할 때 두 개의 별도 컨텍스트가 생성되는 이유는?
① exports 필드가 다른 파일을 가리키기 때문
② Node가 파일 확장자별로 캐시를 구분하기 때문
③ import는 ESM을, require는 CJS를 로드해 각각 실행되기 때문
④ package.json이 중복 로드를 강제하기 때문
③ import는 ESM을, require는 CJS를 로드해 각각 실행되기 때문
import는 ECMAScript Module을, require는 CommonJS 모듈을 로드하며 각각 별도 실행 컨텍스트를 만들기 때문에 동일 패키지가 두 객체로 존재한다.

① Module duplication bug
② Dual package hazard
③ Export field conflict
④ Context mismatch
