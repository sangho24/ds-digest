핵심 포인트

· AI 기반 데이터봇(PANDA)을 통해 팀원이 보안 등급에 맞는 데이터를 실시간 조회 가능

💡 보안 등급 기반 데이터 접근 제어 시스템을 구현해 민감 데이터 유출 리스크를 줄이는 MLOps 프레임워크 개발

핵심 포인트

💡 Lineage MCP를 활용한 테이블 수정 시 자동 영향도 분석 시스템 개발 (예: 스키마 변경 시 영향 받는 파이프라인 30개 자동 식별)

핵심 포인트
· 서비스/모니터링/배치 워크로드를 CPU 우선순위로 분리한 운영 전략
· Resource Group 설정 시 의존 관계를 무시하면 예상치 못한 동작 발생
· StarRocks 3.4 기준 통합 클러스터 내 워크로드 격리 사례 공유
적용 아이디어
💡 데이터 파이프라인에서 Resource Group을 사용해 실시간 조회와 배치 작업을 CPU 우선순위로 분리하여 성능 경쟁 최소화
💡 StarRocks 클러스터 내 A/B 테스트 쿼리와 모니터링 쿼리를 별도 리소스 그룹으로 격리해 QPS 변동에 따른 성능 영향 분석
퀴즈
Q1. StarRocks를 도입한 주요 이유는?
A) MySQL 대체
B) 이중 경로 제거
C) GPU 가속
D) 데이터 압축
정답 보기
✓ B) 이중 경로 제거
MySQL과 Hadoop 간 이중 경로 문제를 해결하기 위해 StarRocks를 도입했으며, 이는 SQL 인터페이스 통합과 대용량 처리를 가능하게 했습니다.
Q2. 워크로드 격리의 핵심 고려사항은?
A) 메모리 최적화
B) CPU 우선순위
C) 데이터 암호화
D) 네트워크 대역폭
정답 보기
✓ B) CPU 우선순위
동시 실행 워크로드가 겹칠 때 CPU 우선순위 설정이 성능 보호의 핵심이며, Resource Group을 통해 이를 관리했습니다.
