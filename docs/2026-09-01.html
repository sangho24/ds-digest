Python의 멀티프로세싱과 Airflow, 그리고 관련된 문제 해결기 1편

Airflow 멀티프로세싱 선택과 한계 파악

AirflowforkspawnGILGit-Sync
원본 보기 →
핵심 포인트
· Airflow는 병렬성과 격리성을 만족하기 위해 task당 별도 프로세스를 생성한다.
· Python 멀티프로세싱에는 fork와 spawn 방식이 있으며, fork는 COW를 이용해 메모리를 공유하고 spawn은 새 인터프리터를 시작한다.
· fork 방식은 메모리 사용량과 모듈 캐시 측면에서 한계가 있어 Airflow에서의 적용에 주의가 필요하다.
적용 아이디어
💡 fork 대신 spawn을 사용해 Airflow task의 메모리 사용량을 최적화한다
💡 task 종료 후 프로세스 폐기를 확인하는 자동화 스크립트를 도입해 모듈 캐시 오염을 방지한다
퀴즈
Q1. Python 멀티프로세싱에서 fork 방식이 메모리를 공유하는 방식을 무엇이라고 하는가?
A) Copy-on-Write
B) Lazy Loading
C) Thread Pool
D) Shared Memory
정답 보기
✓ A) Copy-on-Write
fork는 페이지 테이블만 복사하고 실제 메모리는 쓰기 시 복사되는 Copy-on-Write 방식을 사용한다.
Q2. Airflow가 task 실행 시 만족해야 하는 두 핵심 요구 사항은?
A) 병렬성, 격리성
B) 속도, 확장성
C) 보안, 가용성
D) 신뢰성, 유지보수
정답 보기
✓ A) 병렬성, 격리성
본문에서 Airflow는 병렬성과 격리성을 핵심 요구 사항으로 명시한다.
